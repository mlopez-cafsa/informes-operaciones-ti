Registrar un informe nuevo

Cuando arranca un proyecto o iniciativa de TI que Jefatura/Gerencia debe poder ver.

 Ver detalle ↓Ocultar ↑

Antes de empezar, tené a mano

  • Título del informe.
  • Categoría (por ejemplo: infraestructura, core-financiero, gobierno-ti).
  • Un resumen breve, de 1 a 2 líneas.
  • Prioridad: alta, media o baja.
  • Estado del semáforo: verde (a tiempo), amarillo (en riesgo) o rojo (atrasado).
  • Fecha límite, si aplica.
  • Enlace(s) de Jira, si aplica.

Pasos

  1. Abrí una terminal en la carpeta del proyecto.
  2. Corré el comando de abajo, cambiando los valores entre comillas por los tuyos.
  3. Confirmá que la terminal muestre "Informe creado" sin errores.
  4. Abrí index.html en el navegador y revisá que el informe aparezca con el semáforo y la prioridad correctos.
  5. Subí los cambios a git (commit y push) — ver SOP-01 en SOP.md.

Comando

python3 scripts/manage_informes.py nuevo \
  --titulo "Título del informe" \
  --categoria "Categoría" \
  --resumen "Resumen ejecutivo en 1-2 líneas." \
  --prioridad alta \
  --cumplimiento en_riesgo \
  --estado amarillo \
  --avance 40 \
  --jira-url "https://cafsagroup.atlassian.net/browse/XXX-000" \
  --vencimiento 2026-12-31

Si el informe necesita contenido especial hecho a mano (una tabla o un gráfico propio), avisá antes de correr el comando: hay una forma de "proteger" esa página para que no se borre la próxima vez que el sitio se actualiza.

Registrar un pendiente nuevo

Para anotar una solicitud puntual dirigida a una persona, con seguimiento en el tiempo.

 Ver detalle ↓Ocultar ↑

Antes de empezar, tené a mano

  • Nombre completo y cargo de la persona.
  • Tema, en pocas palabras.
  • Descripción de la solicitud.
  • Nivel de importancia: alta, media o baja.
  • Fecha límite, si aplica.
  • Enlace(s) de Jira, si aplica.

Comando

python3 scripts/manage_pendientes.py nuevo \
  --persona-nombre "Nombre Apellido" \
  --persona-cargo "Cargo — Área" \
  --tema "Tema breve" \
  --solicitud "Descripción de la solicitud." \
  --criticidad media \
  --plazo 2026-12-31 \
  --jira-url "https://cafsagroup.atlassian.net/browse/XXX-000"

Editar o cerrar uno que ya existe

Con el --id exacto (lo encontrás en data/pendientes.json):

python3 scripts/manage_pendientes.py editar --id <id> --estado-item resuelto

El sistema nunca guarda ni inventa una dirección de correo real: el botón "Redactar correo" siempre se abre con el campo "Para" vacío, a propósito — la decisión de a quién enviarlo es siempre tuya.

Actualizar el cargo de una persona

Cuando alguien cambia de puesto, o su etiqueta de jerarquía no es la correcta.

 Ver detalle ↓Ocultar ↑

Cómo funciona

La etiqueta de color (Gerencia / Jefatura / PMO / Operativo) no se escoge a mano: el sistema la calcula solo, buscando palabras clave dentro del texto del cargo.

Si el cargo contiene...Se clasifica como
"gerente", "gerencia", "director", "dirección"Gerencia
"jefe", "jefatura"Jefatura
"pmo", "coordinación" / "coordinador"PMO
cualquier otra cosaOperativo

Comando

python3 scripts/manage_pendientes.py actualizar-persona \
  --persona-slug <slug-tal-como-aparece-en-reportes/> \
  --persona-cargo "Nuevo cargo — Área"

Si el badge queda mal clasificado, no hay forma de forzarlo a mano: hay que ajustar el texto del cargo para que incluya una de las palabras de la tabla. Es intencional, para que la clasificación sea siempre consistente.

Registrar un brief diario

Un resumen de uso estrictamente personal — nunca se publica en el sitio.

 Ver detalle ↓Ocultar ↑

Nombre del archivo (obligatorio)

DD-##-MM-YYYY-brief.html — por ejemplo, 07-01-09-2026-brief.html es el 7 de septiembre de 2026, brief número 1 del día.

Pasos

  1. Colocá el archivo .html dentro de la carpeta briefs/, con el nombre en ese formato exacto.
  2. Corré python3 scripts/manage_briefs.py build.
  3. Abrí (o refrescá) index.html en tu computadora — el botón "Brief del día" aparece solo.

Seguridad: la carpeta briefs/ nunca se sube a git — trae correos y datos reales. Si en algún momento ves que git la quiere subir, detenete y no continúes con la publicación.

Glosario de palabras clave

Todos los términos que hemos ido creando en el proyecto, explicados en simple.

 Ver detalle ↓Ocultar ↑

Estructura del sistema

Informe
El estado de un proyecto para Gerencia — lo que ves en "Tus informes".
Pendiente
Una solicitud puntual dirigida a una persona específica, con seguimiento.
Página de persona
Cada persona con pendientes tiene su propia página, que acumula su historial completo en el tiempo.
Brief diario
Un resumen que hacés fuera del sistema (correo/Teams/Jira) y guardás solo en tu computadora — nunca se publica.

Jerarquía y orden ("Reportes y seguimientos")

Etiqueta de jerarquía
Gerencia / Jefatura / PMO / Operativo — se calcula sola a partir del cargo de la persona (ver la utilidad "Actualizar el cargo de una persona").
Orden de las tarjetas
Primero por jerarquía, luego por cuántos pendientes críticos tiene cada persona, y por último por nombre.
Botón "Redactar correo"
Abre un borrador con el campo "Para" siempre vacío — el sistema nunca guarda direcciones de correo reales.

Cómo se calcula la urgencia

Radar de urgencia
El panel "Mi seguimiento (Jira)" ordena los pendientes por qué tan urgentes son, combinando prioridad y cercanía al plazo — a menor plazo y mayor prioridad, más arriba aparece.
Semáforo de avance
El color (rojo, amarillo, verde) de cualquier porcentaje se calcula con una transición suave, no con saltos bruscos entre colores.

Seguridad y contenido

Disciplina de contenido
Reglas sobre qué nunca puede aparecer en el sitio público: contratos de proveedores, hallazgos de auditoría/SUGEF/CONASSIF, credenciales, IPs internas, o datos sensibles de personas.
Vista local vs. vista pública
En tu computadora ves el detalle completo (incluida esta sección). En el sitio publicado, Jefatura/PMO/Gerencia ven una versión resumida, sin lo que solo te sirve a vos.
Página "protegida" (personalizado)
Una página hecha a mano que el sistema nunca sobrescribe al actualizar el sitio.
